PHASE 2 - DATA STARVATION PROBLEM
================================================================================

CONTEXT:
  - SSL400 dataset: 227 classes, only ~11 videos per class
  - This is EXTREME data starvation for deep learning
  - Model had ~2.29M parameters to learn from ~11 samples/class

WHAT WAS DONE:
  - Implemented temporal augmentation:
      * Time warping (stretching/compressing sequences)
      * Frame drop (randomly removing frames)
      * Time masking (zeroing out random time segments)
  - Added aggressive regularization: dropout=0.5, weight_decay=1e-4
  - Tried to extract pose features → encountered 404 error on MediaPipe pose model URL

ISSUE - POSE MODEL URL 404:
  - MediaPipe pose model download URL returned 404 (model moved/deprecated)
  - Fix: Updated to correct MediaPipe model URL in preprocessing_mediapipe.py

ISSUE - DATALOADER DEADLOCK ON WINDOWS:
  - Training would start then CPU drops to 0%, complete freeze
  - Root cause: MediaPipe uses multiprocessing internally
  - When PyTorch DataLoader (num_workers > 0) spawns workers on Windows,
    MediaPipe's internal processes conflict → deadlock
  - Symptom: Training never progresses past first batch

FIX - PRE-EXTRACTION PIPELINE:
  - Created preprocess_features.py to extract ALL features BEFORE training
  - Runs sequentially (single process), no DataLoader conflict
  - Saves each video's features as .pkl file in data/processed/mediapipe_normalized/
  - During training, DataLoader just reads pkl files (no MediaPipe needed)
  - Set num_workers=0 in DataLoader as extra safety

EXTRACTION RUN:
  - Processed: 2,623 videos
  - Time taken: ~2 hours 4 minutes
  - Failures: 0
  - Feature dims confirmed: 457 per video

  - Model: MultiStreamFusionModel (2.29M params)
  - Epochs: 100

OUTPUT / ACCURACY:
  - Training accuracy:   ~39%  (train)
  - Validation accuracy: ~38%  (val)
  - Test accuracy:       ~24%  (test)
  - Train-Val gap:       ~1%   (almost no overfitting)

PROBLEM IDENTIFIED - UNDERFITTING:
  - Train acc only 39% means the model couldn't learn the training data well
  - Train-Val gap of 1% means regularization is TOO aggressive
  - The model was being prevented from learning by excessive dropout/weight_decay
  - A model that can't fit training data will never generalise well
  - Root cause: dropout=0.5 + weight_decay=1e-4 + 3-layer classifier = too much

DIAGNOSIS: Underfitting (not overfitting)
  - Previous 46% result came from old 1582-dim features (richer face info)
  - New 457-dim features are sparser, need lighter regularization
  - 3-layer classifier (512→256→128→227) was too deep for this problem

PHASE 5 - ROOT CAUSE ANALYSIS OF 6% CATASTROPHE
================================================================================

INVESTIGATION:
  - Checked cache: 2,623 files, all (60, 306), data looks valid
  - Hand part mean: ~0.04-0.18 (non-zero, meaningful values)
  - Face part mean: ~0.01-0.17 (mostly non-zero)
  - Only 1/20 random files had face=0 (some videos have no face detected - normal)

  - Checked checkpoints: val peaked at epoch 9 then DECLINED to epoch 24
    → This is classic OVERFITTING pattern, not data corruption

  - The model memorized 11 training samples/class then failed on val/test

REAL ROOT CAUSE - THREE COMBINED BUGS:

  BUG 1: face_dim_val hardcoded to 232 in dataset/augmenter creation
  -------
  In train_mediapipe.py, the first face_dim_val calculation (for datasets):
    face_dim_val = 60*3 + 52  # 232 (filtered)   ← WRONG, ignores use_blendshapes
  But the second (for model creation) was correct:
    face_dim_val = 60*3 + bs_dim  # 180 or 232
  So StreamSpecificAugmenter was created with face_dim=232 but actual features
  were 180-dim. The augmenter was configured wrong.

  BUG 2: _augment_face_stream silently skipped 180-dim faces
  -----------------------------------------------------------
  In augmentation.py, _augment_face_stream had:
    if face_dim >= 1404:  # 468 × 3 = full face
        # ... augmentation logic
    return face_features  # ← returned unchanged if face_dim < 1404!

  So for face_dim=180 (or 232), NO augmentation was applied to face features.
  This meant the model saw identical face features for each training video on
  every epoch → less diversity → faster memorization → overfitting

  BUG 3: Regularization reduced too aggressively
  -----------------------------------------------
  Changed from: dropout=0.5, weight_decay=1e-4  (38% run)
  Changed to:   dropout=0.3, weight_decay=1e-5  (6% run)
  
  With only 11 samples/class, the weaker regularization allowed the model
  to memorize the training set completely (overfitting)
  Combined with zero face augmentation → catastrophic collapse on validation

================================================================================
KEY LESSONS LEARNED
================================================================================

1. ALWAYS verify cache dims before training
   - Old cache silently passed wrong features to the model
   - The 46% result was on 1582-dim features (not the intended 457-dim)
   - Always print feature_dim at start of training and verify against expected

2. Windows + MediaPipe + PyTorch DataLoader = deadlock
   - Set num_workers=0 is not enough if MediaPipe runs during __getitem__
   - Solution: Pre-extract ALL features to .pkl files first
   - DataLoader then only does file I/O (no MediaPipe), safe with any num_workers

3. Underfitting vs Overfitting diagnosis
   - Underfitting: train_acc ≈ val_acc, both LOW → model can't learn
     Fix: reduce regularization, simplify architecture
   - Overfitting: train_acc HIGH, val_acc LOW (and declining) → memorizing
     Fix: increase dropout, weight_decay; add augmentation

4. Data augmentation for 11 samples/class is CRITICAL
   - Without face augmentation, face features were identical every epoch
   - Same 11 faces × 100 epochs = model memorizes exact face patterns
   - With augmentation, each epoch sees slightly different rotated/scaled faces
   - Effective dataset size increases dramatically with good augmentation

5. Ablation approach for debugging
   - "Strip back to bare essentials first"
   - Disable pose, blendshapes → prove basic hand+face works
   - Then re-add features one at a time
   - This isolates which component is causing problems
